# TabsAI Checkout UI

A lightweight, mobile-first Next.js application for splitting receipt tabs and collecting payments. Designed as an ephemeral web utility triggered by Discord bot interactions.

## Prerequisites

- Node.js 18+
- npm
- A Supabase project with the required tables (see [Database Schema](#database-schema))
- A Stripe account with API keys

## Setup

1. **Install dependencies**

   ```bash
   cd checkout-ui
   npm install
   ```

2. **Configure environment variables**

   Copy `.env.local` and fill in your keys:

   ```
   NEXT_PUBLIC_SUPABASE_URL=https://your-project.supabase.co
   SUPABASE_SERVICE_ROLE_KEY=your-service-role-key
   NEXT_PUBLIC_STRIPE_PUBLISHABLE_KEY=pk_test_...
   STRIPE_SECRET_KEY=sk_test_...
   ```

   - `SUPABASE_SERVICE_ROLE_KEY` is used server-side only for token validation and data fetching.
   - Stripe publishable key is exposed to the browser for Elements. The secret key is used only in the API route.

3. **Run the development server**

   ```bash
   npm run dev
   ```

   The app starts at [http://localhost:3000](http://localhost:3000).

4. **Build for production**

   ```bash
   npm run build
   npm start
   ```

## How It Works

The app supports two flows from the hybrid Discord architecture, keeping users in Discord as much as possible and only breaking out to the web when necessary.

### Authentication Flow

All routes validate a `token` query parameter against the `auth_tokens` table in Supabase. Tokens are:
- Generated by the Discord bot (cryptographically secure, 32-byte URL-safe)
- Time-limited (15-minute TTL)
- Single-use for invitee checkout flows

---

### Scenario A: Even Split

The entire split calculation happens in Discord. The bot asks "Who is splitting this?" via a `UserSelectMenu`, the organizer picks friends, and the engine divides the total evenly. The bot then sends each person a direct payment link.

**Route:** `/checkout/{tab_id}?token={token}&user={discord_user_id}`

1. Server validates the token and looks up the user's Discord ID.
2. Fetches the user's pre-calculated share from the `tab_assignments` table (written by the bot).
3. Renders the Stripe checkout form for exactly their share amount.

The organizer never leaves Discord. Only the paying users open the web app.

---

### Scenario B: Itemized Split

The organizer must break out to the web to do drag-and-drop item assignment, then the bot sends invoices back in Discord.

**Step 1 - Organizer assigns items:**

**Route:** `/split/{tab_id}?token={token}`

- **Add people** - Type a name and press Enter or click Add. Each person gets a color-coded tag.
- **Assign items** - Drag a person's tag from the tag bank onto a receipt item card. Multiple people can share a single item (the cost splits evenly between them).
- **Remove assignments** - Click the X on any assigned tag to unassign them from that item.
- **Summary panel** - Shows each person's calculated total based on their assigned items.
- **Confirm Split** - Persists all item-to-user assignments to the `tab_assignments` table in Supabase and sets the tab status to `assigned`. The bot can then read these assignments and send invoice links in Discord.

The Confirm button is disabled until every item has at least one person assigned.

**Step 2 - Invitees pay their share:**

**Route:** `/split/{tab_id}?token={token}&invitee={name}`

- Shows a summary of all receipt items and the individual's calculated share amount (from `tab_assignments`).
- Renders a Stripe Payment Element with support for cards, Apple Pay, and Google Pay.
- On successful payment, redirects to a confirmation page.

---

### API Routes

**`POST /api/create-payment-intent`**

Creates a Stripe PaymentIntent. Called automatically by the checkout form on page load.

Request body:
```json
{
  "tab_id": "uuid",
  "amount": 1250,
  "invitee": "Alex"
}
```

Returns:
```json
{
  "clientSecret": "pi_..."
}
```

**`POST /api/confirm-split`**

Persists the organizer's item-to-user assignments from the drag-and-drop UI.

Request body:
```json
{
  "tab_id": "uuid",
  "token": "auth-token",
  "assignments": [
    {
      "invitee_label": "Alex",
      "share_amount": 1250,
      "item_ids": ["item-uuid-1", "item-uuid-2"]
    }
  ]
}
```

Returns `{ "success": true }` on success. Also updates the tab status to `assigned`.

## Database Schema

The app expects these Supabase tables (created by the Discord bot):

| Table | Key Columns |
|---|---|
| `auth_tokens` | `token`, `discord_user_id`, `tab_id`, `expires_at`, `is_used` |
| `tabs` | `id`, `creator_id`, `total_amount` (cents), `split_type`, `status` |
| `receipt_items` | `id`, `tab_id`, `item_name`, `unit_price` (cents), `quantity` |
| `users` | `id`, `discord_user_id`, `username` |
| `tab_assignments` | `id`, `tab_id`, `invitee_label`, `share_amount` (cents), `item_ids` (text[]) |
